| **Licence (offline)**           |   ✅   | Offline Ed25519-signed licence file, verified against a public key compiled into the binary — no network, no licence server. Machine-bound (salted hash of the OS machine id) with floating licences supported, inclusive expiry, and a monotonic clock watermark so winding the system date back cannot revive an expired licence. Enforced in the Rust commands, not just the UI: 21 of 29 commands refuse when unlicensed. The baseline stays usable — reading clients and purchases (unsorted, unfiltered, active scope only) plus the language setting. Settings → Licence shows the status, this machine's fingerprint and an import button, and the licence holder's name is the shop name shown beside the logo in the sidebar. Filters and sorting run in the browser, so disabling them is presentational only. The verdict is re-checked every 15 minutes while the app runs, so an expiry takes effect the same day rather than at the next launch — the screen switches to the licence panel on its own and says why.                                                                                                                                                                                                                            |

## Cross-cutting

- **Keyboard accessibility:** forms are tab-navigable, Enter submits, Esc closes modals.
- **Responsive:** grid layouts collapse below ~1200px; minimum window size enforced (1024×680).
- **Toasts:** success/error feedback on all mutations.

## Testing

- **Unit tests (TS):** `npm test` (Vitest) — co-located in `src/**`, covering the finance helpers (`src/lib/finance.test.ts`) and the overdue data/sort logic (`src/views/impayes-overdue.test.ts`).
- **Unit tests (Rust):** `cargo test` from `src-tauri/` — the command layer over a temp SQLite database: installment splitting, transactional rollback on a sum mismatch, every input-validation guard, partial/full/over payment, cascade deletes, atomic settings updates, the migration ladder, and the durability PRAGMAs.
- **Cross-language parity:** `tests/fixtures/finance-parity.json` is read by _both_ `src/lib/finance-parity.test.ts` and the Rust `finance_parity_fixture` test, so `finance.ts` and `db.rs` cannot drift apart silently.
- **Integration tests:** `npm run test:integration` (Vitest, `vitest.integration.config.ts`) — suites in `tests/integration/` drive the real `api` facade against the in-memory backend across multi-command flows: the purchase → schedule → payment lifecycle, overdue/dashboard/cascade-delete consistency, and the error contract (every rejection code resolves to a localized sentence in all three locales, never a raw code or SQL text). Kept out of the default unit run so they stay opt-in.
- **End-to-end tests:** `npm run test:e2e` — self-contained Playwright suite (`tests/e2e/run.mjs`) drives the real app in headless Chromium against the in-memory mock backend. Spawns its own Vite server on port 5199 and pins the browser locale to French for determinism. Covers app-shell render, dashboard KPIs, full sidebar navigation, client list + create flow, purchase list + search, the overdue (impayés) page, and that a rejected payment surfaces localized prose rather than a machine code. Failures capture a full-page screenshot under `tests/e2e/artifacts/`.
